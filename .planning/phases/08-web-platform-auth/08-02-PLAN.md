# Phase 8 Plan 8-02: Patient & Doctor Profiles

> Phase: 8 — Web Platform + Authentication
> Plan: 8-02 — Patient & Doctor Profiles
> Status: Planned
> Depends on: Phase 8-01 (User model, auth endpoints, role dependencies, alembic)
> Delivers: PatientProfile, DoctorProfile, PatientDoctorMapping models; profile CRUD endpoints; doctor→patient assignment endpoints; alembic migration 0002

## Objective

Add profile tables and endpoints so a registered user (patient or doctor) can create/view a profile, and a doctor can view/assign patients. Role-based dependencies (`get_current_patient`, `get_current_doctor`) already exist from 8-01 — this plan builds on them.

## Must-Haves

| # | Requirement | Evidence |
|---|---|---|
| 1 | `PatientProfile` model: one-to-one with User (user_id FK, first_name, last_name, date_of_birth, sex, phone, mrn) | `src/auth/models.py` |
| 2 | `DoctorProfile` model: one-to-one with User (user_id FK, first_name, last_name, license_number, specialization, phone) | `src/auth/models.py` |
| 3 | `PatientDoctorMapping` model: patient_id FK, doctor_id FK, assigned_at, is_active | `src/auth/models.py` |
| 4 | Alembic migration `0002_profiles.py` creating the 3 new tables | `alembic/versions/0002_profiles.py` |
| 5 | `POST /auth/profile` — create current user's profile (branches on role: patient→PatientProfile, doctor→DoctorProfile) | `api/app.py` |
| 6 | `GET /auth/profile` — return current user's profile (role-appropriate) | `api/app.py` |
| 7 | `GET /doctors/patients` — doctor lists assigned patients (requires get_current_doctor) | `api/app.py` |
| 8 | `POST /doctors/patients/assign` — doctor assigns a patient by email (requires get_current_doctor) | `api/app.py` |
| 9 | Role guards: patient accessing doctor endpoints → 403 | dependencies.py (get_current_doctor) |
| 10 | Tests: profile create/retrieve, mapping create/list, role guards, alembic upgrade head | `tests/test_profiles.py` |
| 11 | Full suite green (existing 86 + new profile tests) | `pytest tests -q` |
