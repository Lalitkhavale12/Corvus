# Phase 8 Plan 8-03: Authenticated Predictions & History

> Phase: 8 — Web Platform + Authentication
> Plan: 8-03 — Authenticated Predictions & History
> Status: Planned
> Depends on: Phase 8-02 (profiles + mapping), Phase 3 (v2 serving endpoints)
> Delivers: JWT-protected /v2 predict + batch_predict, user-linked prediction rows, GET /auth/predictions history endpoint

## Objective

Protect the v2 prediction endpoints behind authentication so every prediction is linked to the user who made it. Add a prediction-history endpoint so users can view their own past predictions. Frontend connects PredictionHistory and PatientDetail to the backend instead of localStorage.

## Must-Haves

| # | Requirement | Evidence |
|---|---|---|
| 1 | `user_id` column on `PredictionLog` (predictions table) — FK to users.id | `api/db.py` |
| 2 | `user_id` column on `PredictionLogV2` (predictions_v2 table) — FK to users.id | `api/db.py` |
| 3 | Alembic migration `0003_user_id.py` adding user_id to both tables | `alembic/versions/0003_user_id.py` |
| 4 | `POST /v2/predict` requires authentication (get_current_patient or require_user), links row to current_user.id | `api/app.py` |
| 5 | `POST /v2/batch_predict` requires authentication, links rows to current_user.id | `api/app.py` |
| 6 | `GET /auth/predictions` — returns current user's prediction history (both v1 and v2 rows) | `api/app.py` |
| 7 | `GET /auth/predictions/{id}` — returns a single prediction if owned by current user | `api/app.py` |
| 8 | `PredictionHistoryOut` schema: id, model_version, prediction, probability, created_at, source fields | `api/schemas.py` |
| 9 | Tests: protected predict (401 without token), history returns own rows, history excludes other users' rows, single prediction 404 for wrong owner | `tests/test_predictions.py` |
| 10 | Full suite green | `pytest tests -q` |

## Notes

- `user_id` nullable=True during migration (existing rows), code always populates it for new rows.
- Both patients and doctors can make predictions (require_user), linked to their user_id.
- History endpoint returns combined v1 + v2 rows for the current user.
- PredictionHistory.jsx currently uses localStorage (`src/lib/history.js`) — this plan replaces that with backend calls.
- PatientDetail.jsx "Run New Prediction" uses NhanesForm → predictionAPI.predict, which already attaches JWT via interceptor; just needs to also refresh history after save.
