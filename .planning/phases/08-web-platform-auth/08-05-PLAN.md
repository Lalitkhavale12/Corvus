# Phase 8 Plan 8-05: Docker Compose + Local Deployment

> Phase: 8 — Web Platform + Authentication
> Plan: 8-05 — Docker Compose + Local Deployment
> Status: Planned
> Depends on: Phase 8-02 (profiles + mapping), Phase 8-03 (authenticated predictions)
> Delivers: Production-ready docker-compose with env-driven secrets, frontend service, local run verification

## Objective

Finalize the Docker Compose stack so the entire Corvus app (db, api, mlflow, frontend) can be brought up locally with a single command, using environment-driven secrets (no hardcoded SECRET_KEY) and VITE_API_URL passed at build time.

## Must-Haves

| # | Requirement | Evidence |
|---|---|---|
| 1 | `.env` file at repo root with SECRET_KEY, DATABASE_URL, VITE_API_URL (gitignored) | `.env` |
| 2 | `.gitignore` excludes `.env` | `.gitignore` |
| 3 | `config.yaml` reads `auth.secret_key` from env `SECRET_KEY` with fallback | `config/config.yaml` |
| 4 | `docker-compose.yml` references `.env` file | `docker/docker-compose.yml` |
| 5 | `api` service gets `SECRET_KEY` from environment | `docker/docker-compose.yml` |
| 6 | `frontend` service gets `VITE_API_URL` as build arg | `docker/docker-compose.yml` |
| 7 | `frontend` build uses `VITE_API_URL` for API base URL | `docker/Dockerfile.frontend` |
| 8 | `docker compose up -d` brings up all 4 services healthy | `docker compose ps` |
| 9 | End-to-end: register → login → predict → history via browser at localhost:3000 | Browser verification |

```yaml

  secret_key: "${SECRET_KEY:corvus-dev-secret-change-in-production}"
  algorithm: "HS256"
  access_token_expire_minutes: 30
```

## Dockerfile.frontend Changes

```dockerfile
ARG VITE_API_URL=http://localhost:8000
ENV VITE_API_URL=$VITE_API_URL
# ... build with VITE_API_URL available at build time
```

## Notes

- `src/utils/config.py` needs env var substitution support for `${VAR:default}` syntax
- Frontend build needs VITE_API_URL at build time (Vite embeds it into the bundle)
- The nginx stage serves the built static files; API calls from the browser go to VITE_API_URL
- SECRET_KEY fallback is dev-only; production must set it explicitly
