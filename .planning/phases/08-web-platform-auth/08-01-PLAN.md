# Phase 8 Plan 8-01: Backend Auth Foundation

> Phase: 8 — Web Platform + Authentication
> Plan: 8-01 — Backend Auth Foundation
> Status: Planned
> Depends on: Phase 3 (FastAPI, MLflow, Docker Compose, PostgreSQL)
> Delivers: SQLAlchemy ORM, Alembic migrations, User model, bcrypt password hashing, JWT auth, /auth/register, /auth/login, /auth/me, protected route dependencies

## Objective

Add authentication to the existing FastAPI backend so patients and doctors can register, log in, and access protected prediction endpoints. No frontend yet — this is API-only, verified via tests and curl.

## Must-Haves

| # | Requirement | Evidence |
|---|---|---|
| 1 | SQLAlchemy models for `users` table (id, email, password_hash, role, google_id nullable, is_active, created_at) | `src/auth/models.py` |
| 2 | Alembic migrations initialized and first migration created | `alembic.ini`, `alembic/versions/` |
| 3 | Password hashing with bcrypt via passlib | `src/auth/security.py` |
| 4 | JWT access tokens with expiration via python-jose/PyJWT | `src/auth/auth.py` |
| 5 | `POST /auth/register` — email + password + role (patient/doctor), returns user without password | `api/auth_routes.py` or added to `api/app.py` |
| 6 | `POST /auth/login` — email + password, returns JWT access token | `api/auth_routes.py` or added to `api/app.py` |
| 7 | `GET /auth/me` — returns current user profile from JWT | `api/auth_routes.py` or added to `api/app.py` |
| 8 | `get_current_user` dependency — extracts JWT from Authorization header, returns user or 401 | `src/auth/dependencies.py` |
| 9 | `get_current_patient` and `get_current_doctor` role dependencies | `src/auth/dependencies.py` |
| 10 | Existing `/v2/predict` and `/v2/batch_predict` remain functional (auth optional for now, enforced in 8-03) | No breaking changes to existing routes |
| 11 | `SECRET_KEY` and `ALGORITHM` config keys added to config.yaml | `config/config.yaml` |
| 12 | Tests: register, login, login with wrong password, get me with valid/invalid token, role dependencies | `tests/test_auth.py` |
| 13 | Full suite still green (existing tests + new auth tests) | `pytest tests -q` |

## Acceptance Criteria

- [ ] `alembic upgrade head` runs successfully against local PostgreSQL
- [ ] `POST /auth/register` with new email + password + role returns 201 + user object (no password_hash)
- [ ] `POST /auth/register` with duplicate email returns 400
- [ ] `POST /auth/login` with correct credentials returns 200 + access_token
- [ ] `POST /auth/login` with wrong password returns 401
- [ ] `GET /auth/me` with valid Bearer token returns 200 + user object
- [ ] `GET /auth/me` with invalid/expired token returns 401
- [ ] `get_current_patient` rejects doctor role with 403
- [ ] `get_current_doctor` rejects patient role with 403
- [ ] Full test suite: existing 74 + new auth tests, 0 failed

## Notes

- Role values: `"patient"` and `"doctor"`
- Users self-register; no admin approval gate (D-16)
- Google OAuth deferred (D-15)
- Existing v1 and v2 routes remain unauthenticated in this plan; auth enforcement added in 8-03
- Database tables created via Alembic, not SQLAlchemy `create_all` (production best practice)
