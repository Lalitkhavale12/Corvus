<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP client -> /batch_predict | Untrusted CSV file crosses into server-side parsing and per-row validation |
| Batch handler -> Postgres | Multi-row write must commit atomically to avoid partial log state |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-07 | Denial of service | POST /batch_predict upload | high | mitigate | MAX_BATCH_BYTES 5000000 plus MAX_BATCH_ROWS 10000 rejected with 413 before full parse; no new packages, no auto-approval involved |
| T-03-08 | Tampering | batch CSV columns | medium | mitigate | Exactly-24 requirement with missing-column 422, lineage plus target dropped via imported constants, unexpected extras warn-logged and ignored never fed to the pipeline per D-07 |
| T-03-09 | Tampering | batch log atomicity | medium | mitigate | All-or-nothing per D-08: every row validated with first-offender row number before any commit, single commit after all predictions, zero rows written on rejection |
| T-03-10 | Information disclosure | batch CSV display | low | accept | Server never renders CSV as formulas and Streamlit shows results via st.dataframe text cells, so no formula-evaluation path exists |
| T-03-11 | Tampering | PredictionLog SQL | medium | mitigate | SQLAlchemy ORM-bound parameters exclusively; no string-built SQL in api/ |
</threat_model>
